## Frontend layer (`integrations/yoagent-frontend/`, EXPERIMENTAL, separate crate)

`publish = false`, no API promise; neither yoagent's core nor yoagent-rutis's API depends on it (its one touch outside: the pi adapter's optional dialogs, below). `Session::new(accept_quit) -> (Session, Driver)`: `Driver::run(agent) -> Agent` owns the agent; the `Driver` holds an `Ending` guard, so however it goes (returns, its task panics or is aborted, or it is dropped unrun) an open run gets `RunEnd{outcome: Error}`, the session is marked closed and every frontend gets `Closed`. `Session` (clone; only handles hold the command sender, so dropping them all ends the driver): `connect()` → `Connection { id, messages }` (own unbounded channel per frontend, `Hello` first, then the replay of `Inner.history` (the last `HISTORY` = 5000 `runStart`/`event`/`runEnd`/`notice` broadcasts, recorded in `Inner::broadcast` under `clients` then `history`, so a late frontend gets each message once; kept across a reset; questions not included — Hello carries the open ones) — then `Closed` at once if the session ended — built under the clients lock, nothing dropped; **lock order is `clients` → `ui`**: never take `clients` (`frontends()`, `broadcast`) while holding `ui`), `send(ClientMessage) -> bool` (false + `warn!` once closed; a `UiResponse` resolves its question only if `UiRequest::accepts` the value — confirm: bool, select: an option or null, input: string or null — else it stays open), `is_closed`, `notice(level, msg)`, crate-private `send_to(id, msg)`, `ask(UiRequest, timeout)` / `ask_keyed(.., key)` (no frontend → `default_answer` at once, logged; else broadcast `UiRequest`, first fitting answer wins; a `Close` guard removes the entry however `ask` ends and broadcasts `UiResolved{id, reason: Answered|TimedOut|Withdrawn}`; a key already in use is not taken over (warned) and the guard removes a key only if it maps to its own id), `ask_later(request)` (= `ask_inner(.., timeout None, hold true)`: kept open with no frontend attached (later ones get it in `Hello`), no timeout; the `Ending` guard clears `pending` under `clients` → `ui`, and `ask_inner` returns the default when `is_closed()` under the `ui` lock, so a held question never outlives the session), `withdraw(key)` (unknown key → remembered 60 s, so a withdrawal that overtakes its question returns the default without showing it), `add_ui_plugin(UiPlugin, module) -> Option<u64>` (the version; empty name → `None`), `remove_ui_plugin(name, Option<version>)`, `ui_plugin_module`. Protocol (`protocol.rs`, tag `type`, camelCase, enums `#[non_exhaustive]`): in `prompt`/`steer`/`followUp`/`abort`/`reset`/`uiResponse`/`quit`; out `hello{running,uiPlugins,uiRequests}`, `runStart{run,prompt}`, `event{run,event}` (text/thinking deltas merged by `Coalesced`, held ≤30 ms), `runEnd{run,outcome: RunOutcome(completed|aborted|rejected|error),error,stats,totalCostUsd}` (always once per run; no `AgentEnd` → `error` + an error `Notice`; `InputRejected` → `rejected`; Abort/Reset/Quit → `aborted`; else the last assistant message), `uiRequest`/`uiResolved{id,reason}`, `notice{level,message}`, `uiPlugins`, `closed`. `UiPlugin.version` is `skip_deserializing` (set by the session). Prompt mid-run → queued; steer/followUp idle → a prompt; steering/follow-ups the loop never read (they arrived after its last look, e.g. while extensions `finish`) become the next run's prompt unless the run was aborted (a reset clears them); `Reset` mid-run aborts, drops the queue and clears history after `finish`. `services::provide(root, &session)`: host services `frontend` (`connect(client)` sync → `client.receive(msg)` per message in order, raced against the disposer / the caller's `Connection::closed`, a failed `receive` disconnects it; `send` async, `Err` once closed; `addUiPlugin(info, module)` sync → disposer removing that version only, `Err` on an empty name) and `ui` (`frontends()` sync → the attached count; `request(request, timeoutMs?)` → `Value::future`; `key` must be a string, `timeoutMs` null or a finite non-negative number (fractions ok); `withdraw(key)` string only); unit tests drive `invoke` directly. `web::serve(session, addr) -> Served` (private fields; `url()`, `addr()`, `token()`, `stop()`; dropping it stops serving) (axum 0.8, `ws`): `/`, `/app.js`, `/lib.js` (embedded `web/`), `/favicon.ico` 204, `/ui-plugins/{name}` (`.js`), `/ws` **requires `?t=<token>`** (uuid v4; 403 otherwise — WebSockets skip CORS, so without it any page could drive the agent); a frame that is not the protocol → `warn!` + a `Notice` to that frontend; UI plugin modules are trusted code. Page: `web/lib.js` (no DOM; `web/package.json` marks `web/` as ESM — the terminal UI imports it, and rutis's loader would read it as CommonJS: `toolView(details)` (only the six card kinds), `viewTitle`, `diffRows` (LCS; unaligned when old × new line counts exceed 400²), `parseAnswer(request, text)` (the terminal UI's typed answers: `{value}` or `{error}` → asked again, never guessed), `safeUrl` (http(s)), `markdownParts` (https links only), `Questions` FIFO, `runEndLine`), tested by `node --test web/lib.test.js`; questions are a docked, non-modal `<dialog>` (`show()`, fixed above the composer, `body.asking` pads the log, "1 of N questions waiting") — the page stays usable while one waits; `app.js` handles messages serially (a promise chain), refuses to send on a closed socket or ended session (says so; the prompt stays in the box, a dialog stays open). `host::PluginHost::builder().node(name, dir).share(svc).start(root)` → `load(rows)` (`Row::new(id, name).runtime(r).config(..).inject(..)`; a `Routed` resolver sends a row to its named runtime, others to the first that resolves; a name already routed to another runtime is refused) waits until rows are `Active` (reconcile counts `Pending` as settled), errors naming those that are not; a failed batch is dropped (rows and routes restored; a failed rollback is logged); `status()`; `unload(id)` (row dropped, its route too when no other row loads that name, reconcile; restored on failure) and `reload(id)` = `RuntimeResolver::invalidate(name)` on every runtime's resolver (kept in `PluginHost.runtimes`) + `Loader::reload(id)` (re-describe → the runner's `fresh()` imports the changed file with a `?rutis-reload=<mtime-size>` query → row replaced) + wait until it runs. **Not atomic:** a module that fails to import/describe is refused before anything stops (old version keeps running), but one that fails in `apply` has already replaced the old row, and the loader's rollback re-imports the same (new) file — the plugin stays `Failed` until a later reload succeeds; the error says "running version stays" or "is stopped" (by `is_running(id)`); the example runs `.require_policy()` so a stopped pi policy denies calls. `load` waits only for the rows it added and fails only on `new_failures`, `unload` waits for none — a stopped plugin does not block other changes. **Without `invalidate`, `Loader::reload` is a no-op** for a Node file row (the resolver caches by package version, and a lone file has none) and `Loader::restart` re-applies the already-imported module. Only the plugin's own module is re-imported (not its imports); a `.ts` plugin must sit in a `"type": "module"` package (tsx loads it as CommonJS otherwise, whose cache ignores the query); pi extensions reload with the pi adapter (pi's jiti loader, `moduleCache: false`). `tests/host_test.rs` (temp ESM `.ts` plugin with a `version` tool: edit → new code, unchanged reload restarts, a syntax error refused with the old code kept, an `apply` that throws leaves it stopped (and another plugin still loads), the next good save brings it back, unload removes the tool). **A TS row is Active before its async `apply` finishes** — wait for the handlers you depend on. **A row-level `inject` on a TS row stops it from ever applying** (don't; re-provide instead, as `host-ui.ts` does). Plugins (`plugins/`, own `package.json`: rutis 0.8.0, pi-tui 1.1.0): `terminal-ui.ts` (pi-tui on `frontend`; `/dev/tty` keyboard; questions answered in the editor, a stale prefill cleared when its question closes; `receive` never throws (shown instead); a failed quit goes to stderr; `demo` headless prints `[header, log, status]` and declines questions), `search-links.ts` (UI plugin: `renderTool` links for search tools, `mountPanel` quick prompts), `pi-extensions/confirm-dangerous.ts` (a pi permission gate using `ctx.ui.select`). pi dialogs: rutis shows a **host** service only to plugins that inject it and starts a plugin only once all injected services exist, so `yoagent-rutis/plugins/pi/host-ui.ts` injects `ui` and re-provides it in the pi runtime as `pi-host-ui`; the adapter looks that up per pi context (`lookupUi`; missing → print mode, said once at debug) → RPC mode (`mode: 'rpc'`, `hasUI: true`, `select`/`confirm`/`input`/`editor`/`notify` forwarded; failures → print-mode answers); each question keyed `pi-<randomUUID>` and withdrawn on its signal's abort (a failed withdraw is reported at warn); without it, print mode unchanged. `examples/minimal_browser.rs`: the smallest use — `Session::new(false)` + `web::serve` + an agent with read-only tools (`list_files`, `read_file`, `search`) sandboxed to the cwd (`with_allowed_paths`; the built-ins allow every path by default), no plugins or Node; scripted, or `--live` DeepSeek; tried live in Chrome. `examples/coding_agent.rs`: runtimes `ui`/`pi`/`dsh`, terminal (default) or `--web [ADDR]` (8787), `--demo`, `--live` (`DEEPSEEK_API_KEY`), `--no-dsh`, `--watch` (a task owning the `PluginHost` polls the plugin files every 500 ms by mtime + size — row files, the pi extension → `pi`, terminal-ui in terminal mode — settles 200 ms (files changed meanwhile are reloaded too), `reload`s the owning row and sends every frontend a `Notice` — Info, Warning when the old version stays, Error when the plugin is stopped; tried live in Chrome: an edited pi extension's new question text, a broken save refused); waits for `pi-extensions`/`dsh-tools` handlers; `tracing-subscriber` (stderr with `--web`/`--demo`, else `$TMPDIR/yoagent-coding-agent.log`); a shutdown error never hides the run's. Tool cards: a result's `details.view` (DSH's card vocabulary) is drawn by `app.js` `card()` (terminal/diff/search/read/web/generic; `CARD_LINES` 200 per block, ≤20 web sources; a generic card with no text draws nothing; a card that throws → "(this tool's card could not be drawn)") unless a UI plugin draws that tool; the line takes `viewTitle` (browser: only then; terminal UI: always). `UiRequest::Select { title, message, options, multiple }` (answer: a list of distinct options with `multiple`; a frontend that cannot offer several must leave it unanswered), `Input` has `message` too; `ask_keyed` asks `request.normalized()` (a select's options each once). Tests: `session_test` (19, a `Gate` tool keeps runs in progress), `web_test` (4, tokio-tungstenite), `pi_dialog_test` (real pi runtime: Allow runs `bash`, Block stops it; skipped without `plugins/pi/node_modules` unless `YOAGENT_RUTIS_REQUIRE_RUNTIMES=1`), `dsh_dialog_test` (real DSH runtime: approval yes/no, `ask_user_question`, `details.view`; stopping a run withdraws its open approval (`UiResolved` withdrawn, `RunEnd` aborted, tool not run); skipped without `plugins/dsh/node_modules/@deepseek-ai/dsh-tool-ask-user` — re-run `npm ci` after a lock change), unit tests (`Coalesced`, services, `UiRequest::accepts`); CI job `frontend-experimental` (fmt, clippy, docs, tests with runtimes required, `node --test`, headless example asserting the pi question reached the terminal UI and `bash ✗`). Tried live in Chrome (DeepSeek + DSH search, links rendered by the UI plugin).

`scripts/try-coding-agent.sh` (repo root): checks cargo / Node 24+ / npm, `npm ci` in the three plugin dirs when `node_modules/.package-lock.json` is missing or older than the lockfile, then runs `coding_agent` with `--web` unless `--terminal` (or `--web`/`--demo` given); `--setup-only`; `--live` needs `DEEPSEEK_API_KEY`; empty-array expansions are bash-3.2 safe.

`examples/handoff_agent.rs` + `scripts/try-handoff.sh` (runs in the caller's cwd; `try-coding-agent.sh --setup-only` first): pi rows (adapter with `plugins/node_modules/@juicesharp/rpiv-todo/index.ts` + `confirm-dangerous.ts`; `plugins/package.json` pins `@juicesharp/rpiv-todo`/`rpiv-i18n` 2.12.0, `plugins/.npmrc` `legacy-peer-deps=true` — `npm ci` refuses the lock otherwise: pi's packages come from the adapter, never installed there), `pi-host-ui`, `todo-plan` UI plugin (`renderTool` for `todo` from `details.tasks`), DSH search (no `ask_user_question`: blocking). `AskOwner` tool (Select with ≥2 `options`, else Input; returns at once; a spawned task awaits `ask_later` → `Some(answer)` → `ClientMessage::Steer` `[Owner's answer to #N] …` / `[Owner skipped #N] …`; `None` (withdrawn by a reset — `Inner::withdraw_held` drops `UiState.held` questions — or the session ended) → nothing). `Start { head, tree }`: `tree` = `git stash create` (a commit of the uncommitted tracked edits; files, index and stash list untouched) else `head`; the diff is against `tree`, commits counted from `head`. The scratch folder is made in `main` and exported as `YOAGENT_SCRATCH` before the runtime starts; `confirm-dangerous.ts` exempts it and files the agent created this session (paths compared via `realpath`), and asks for `rm`/`unlink`/`rmdir` (globs always), `mv`/`cp`/`>` onto an existing file, writes over an existing file, `git reset --hard`/`clean`/`checkout --`/`restore`/`branch -D`/forced push, `find -delete`, `truncate`/`shred`/`mkfs`/`dd`/`sudo`/`ch{mod,own} -R`, `.env`/`.git/`. The scripted demo does what its reports say (run 2 writes `notes.md`; checked, with the facts naming it). `Handoff` extension: `on_stop` requires the four `REPORT` headings (Continue otherwise), `on_event` counts tokens/tool calls, `finish` → `Notice` facts (diff/commits vs the HEAD at launch, untracked files new since launch (named, ≤3), tokens, tool calls, time, open questions). Limits 80 turns / `--max-tokens` (4M: research reads a lot; yoagent's 1M default counts the whole prompt each turn) / `--max-minutes`; a `RunEnd::Stopped` run gets a Warning notice ("Stopped early: … send continue"); scratch goes to `$TMPDIR/yoagent-handoff-<pid>` (named in the prompt: only deliverables in the cwd; search tools, not whole downloaded pages; write the deliverable early); a repo with no commit compares against git's empty tree (`EMPTY_TREE`); `Budget::for_model(..).across_runs()` only when priced (`prices::enable_bundled()`; DeepSeek unpriced). `with_tools` replaces the list (one vec of `default_tools()` + `AskOwner`). `--demo`: `Session::new(true)` (tools hold session handles, so it ends with `Quit`), a connected frontend answers #1 after run 1 → run 2; self-checks; in CI (`frontend-experimental`). Tried live (DeepSeek, phone-sized Chrome, a scratch Python repo).
